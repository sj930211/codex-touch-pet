# Codex Touch Pet 像素宠物候选测试

本目录是视觉候选测试隔离区，不属于正式应用资源，也不会被 Package.swift、Makefile 或 Sources 自动加载。

## 当前状态（2026-09-18）

- B 三轮方案已确认，但三轮用户测试均未开始。
- 内置生图请求返回 HTTP 503 / `auth_unavailable`，没有生成候选位图；未切换到需要密钥的 CLI。
- 原始代码草图只改变局部颜色，尚不具备可测试的状态姿态；未连接和过期甚至使用相同图形，不能作为有效候选。
- `index.html` 暂时只保留准备状态，不开放盲测或评分。
- 候选素材自检通过、用户选择第二轮候选后，才开始独立真机测试；网页 CSS 像素尺寸不能冒充 Touch Bar 真机尺寸。
- 生成规格保存在 `GENERATION_PROMPT.md`，不存在已批准的美术资源。

## 候选方向

- A / 几何小机器人：方形轮廓、面板眼睛，优先测试状态清晰度。
- B / 小型像素动物：耳朵与尾部轮廓，优先测试亲和力和陪伴感。
- C / 像素小生物：团子轮廓、单一视觉重心，优先测试小尺寸稳定性。

这些名称只是测试代号，不代表正式角色、动物或品牌设定已经确定。

## 三轮测试

### 第一轮：静态识别

候选素材就绪后再开放盲测：隐藏提示文字和无障碍标签中的答案，打乱状态顺序，逐次记录作答。展示 9 种状态：空闲、正在工作、等待确认、等待回复、已完成、任务失败、系统异常、未连接、状态过期。

每次记录候选代号、显示尺寸、猜测状态、是否需要文字提示、是否把普通工作误判成错误。

建议通过门槛：

- 工作、等待、严重错误三类的盲测正确率至少 80%；
- 不看颜色时仍能区分工作、等待和错误的姿态；
- 窄入口尺寸下主体轮廓不糊成同一个符号；
- 没有候选长期被误认为红色系统异常。

未达到门槛的候选不进入第二轮；若多个候选达到门槛，保留前两名。

### 第二轮：真实 Touch Bar

只把第一轮前两名放入临时测试开关，不能替换正式宠物。测试其他应用前台的窄入口、ChatGPT/Codex 前台的完整状态面板、单任务和多任务汇总、等待确认、等待回复、完成、错误和断线恢复、应用切换、点击入口、系统控制条让位与恢复，以及减少动态模式。

记录真实尺寸下的裁切、跳动、状态误读、触控命中和系统控制条冲突。

必须保持已确认语义：工作主状态为“Codex 正在工作”；多任务只显示汇总；红色只表示当前有效严重错误；具体任务仍回到 Codex 查看。

### 第三轮：长时间低干扰

对第二轮前两名进行 30–60 分钟实际工作观察：工作循环不能造成持续注意力打扰；等待和严重错误要能被发现但不能高频闪烁；完成反馈只播放一次；普通工作不能长期显示为“调用工具”或红色异常；标准动效和减少动态模式都要可辨识。

第三轮通过后，才允许把候选写入正式美术需求和技术实现。未通过的候选只保留在本目录作为测试记录。

## 评分表

每项 1–5 分：

| 维度 | 1 分 | 5 分 |
|---|---|---|
| 小尺寸轮廓 | 看不清 | 一眼可辨 |
| 状态区分 | 经常混淆 | 几乎不混淆 |
| 非颜色识别 | 只能靠颜色 | 姿态/符号足够表达 |
| 低干扰 | 很吵、很抢注意 | 安静但不会错过 |
| 亲和力 | 无个性或令人反感 | 有记忆点但不喧宾夺主 |
| Touch Bar 适配 | 裁切、跳动或遮挡 | 稳定、清晰、可让位 |

建议门槛：总分至少 24/30，且“状态区分”“Touch Bar 适配”不得低于 4 分。

## 测试边界

- 不记录提示词、回复正文、任务标题、命令、文件名或线程 ID。
- 不把测试中的视觉偏好当作当前会话监控能力。
- 不在测试未通过前创建正式资源名、正式角色故事或皮肤系统。
- 不修改现有 Sources/CodexTouchPet/TouchBarController.swift 的正式回退宠物。
